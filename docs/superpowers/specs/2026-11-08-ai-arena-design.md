# AI 对局接入与归档

用户已授权实施；成片暂不制作。保留现有引擎、普通房间、MCP 与 Web 界面。

## 信息契约
- 每个 AI 只获取自己的手牌、身份、私密技能提示、自己的记忆与策略说明，以及全场公开状态和发言。
- 公共上下文包含公开武将、血量、装备、判定区、主公与死者身份，不含他人手牌、存活非主公身份、私密看牌结果。
- 观众视图展示全部手牌，仍隐藏存活非主公身份。观众数据不用于生成 AI 输入。
- 观星、恂恂等观看牌堆只给操作者；展示、判定类公开牌面给所有人。默认不显示整副牌堆顺序。
- 思考日志是模型显式输出的简短策略说明与持续记忆，不要求或伪称获取模型内部推理链。

## 接入与归档
- TypeScript/Node 运行器，按玩家配置 API、外部 MCP 或启发式基线。API 适配 OpenAI-compatible 与 Gemini REST；无新增 SDK。
- API 与 MCP 共用观察投影、决策菜单、记忆和归档模块。MCP 可继续使用旧 play(action)；新增 actionId、memory、strategySummary、publicSpeech。
- 每位 AI 的消息历史与 memory 独立。公共消息、观众帧和每位 AI 的决策/观察分文件保存。
- 运行器生成 MCP 配置与加入提示；外部 agent 登录同一配置账号接替该座位，其他座位可继续用 API。
- 每局独立目录 data/arena/<matchId>，保存 manifest、public.jsonl、audience.jsonl、players/* 与最终 replay.json，不跟随房间清理删除。
- 提供观众页和归档列表，主要用于验证所有手牌展示和思考日志；不做视频、配音或复杂导演系统。

## 验收与范围
- 先完成主体再集中测试，按用户要求不做逐步 TDD、不增加高要求安全与容错系统。
- 验证信息隔离、私密/公开看牌、菜单提交、独立上下文、归档，以及真实房间完整对局。
- 在能找到授权环境凭据时做小规模真实模型验证；日志不保存密钥。
